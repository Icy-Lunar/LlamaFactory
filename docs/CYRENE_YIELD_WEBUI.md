# Cyrene Yield 训练界面：现行说明与改进点

> 更新日期：2026-11-03
> 基础项目：LLaMA Factory
> 集成目标：`Cyrene-Yield/develop/plugins/llama-factory-training`

## 与原版 LLaMA Factory 的主要差异

| 项目 | 当前实现 |
| --- | --- |
| 产品范围 | WebUI 保留引导式训练、Hugging Face 快速对话测试和适配器合并；CLI 业务入口只保留训练与模型合并/导出。 |
| 模型来源 | 只读取本机已有模型目录，不提供 Hugging Face、ModelScope 或其他模型下载入口。 |
| 初始配置 | 用户先选择 Full、Freeze、LoRA 或 OFT 微调以及是否量化；系统再根据训练目标、优化重点、检测到的 GPU 和本地权重文件大小生成其余推荐值。 |
| 参数展示 | 根据 SFT、PT、DPO、RM、PPO、KTO 显示当前阶段的按需参数；表单提供五语“？”帮助。LoRA 参数和多模态参数仅在适用时出现。 |
| 量化与加速 | 训练量化仅保留 `bnb`，可选不量化、8 位、4 位；Liger 通过设备、精度和模型兼容检查后启用，否则使用普通训练。移除其他后端选项及合并页的 GPTQ 量化入口，保留适配器合并。 |
| 训练内验证 | 支持不验证、按百分比划分或使用独立验证集；比例划分默认保留 10%。验证周期自动等于保存周期，每保存一次检查点就验证一次，不增加单独的验证步数输入。PPO 不显示不支持的验证面板。 |
| 显存检查 | 参数配置阶段实时读取 `config.json`、本地权重文件和当前训练配置，估算单设备峰值并增加 10% 安全余量；启动前使用相同口径再次检查。 |
| 风险控制 | 显存不足、低于建议值或无法检测时不推荐启动；强制训练必须在警告窗口中二次确认。 |
| 多语言 | 可见文本集中在本地化资源中，当前支持英语、俄语、简体中文、韩语和日语，默认显示简体中文。 |
| 适配器合并 | 保留本地适配器合并；Hub 上传和原始 JSON 参数不再出现在 WebUI 中。 |
| 快速测试 | 读取本地基础模型和可选 LoRA 目录，固定使用 Hugging Face Transformers 流式生成；不提供 vLLM、SGLang 或额外后端参数。 |

## 当前四步流程

1. **模型与目标**：输入包含 `config.json` 和权重文件的本地模型目录，选择 Full、Freeze、LoRA 或 OFT 微调、量化方案、训练目标和优化重点。量化默认关闭，不再强制启用 4-bit；硬件自动检测，推荐配置随选择即时更新。Full 和 Freeze 微调按照框架兼容性要求使用非量化权重。
2. **选择数据**：只展示与训练目标匹配的数据集。预览按钮始终可点击；未选择、文件不存在或格式错误时显示当前语言的处理建议。预览第一个所选本地数据集的前 100 条以内记录，每页 2 条，支持 JSON、JSONL、CSV、TXT、Parquet 和 Arrow。切换目录或数据集会清空旧预览。
3. **按需调整**：可直接采用推荐值，也可以只修改显存/速度参数或学习质量参数。常用参数区提供最大样本数、学习率调度、梯度裁剪、随机种子、日志/保存/预热步数；阶段专属参数见下表。还可按需启用训练内验证。LoRA 分支另提供 rank、alpha、dropout、RS-LoRA 和 DoRA。检测到多模态模型时才显示视觉塔、视觉投影器、语言模型冻结开关以及图像/视频像素范围。相关参数改变后显存自动重算。
4. **安全检查**：确认输出目录和配置，使用最终参数重新执行显存检查；通过后显示训练按钮。

训练启动时，最终配置会自动保存到任务输出目录，不再要求用户单独管理配置文件。

| 阶段 | 第三步的专属设置 |
| --- | --- |
| SFT | 样本打包、词表扩展、提示词参与训练、历史轮次掩码、无交叉打包、NEFTune 噪声 |
| PT | 样本打包、词表扩展，以及通用学习与资源参数 |
| DPO | 偏好系数、监督损失权重、损失类型；按损失类型显示标签平滑或 SimPO 间隔 |
| KTO | 偏好系数、正反馈与负反馈权重 |
| RM | 奖励模型训练说明，使用通用参数与可选验证集 |
| PPO | 奖励模型路径、更新轮数、经验缓冲区、目标 KL、分数归一化、奖励白化 |

切换阶段后，其他阶段隐藏控件的遗留值不会写入本次训练参数。验证默认关闭；开启比例划分时可从 10% 和验证批大小 1 开始，界面百分比会转换为训练配置中的小数比例（例如 `10` 转换为 `val_size: 0.10`）。生成的配置使用 `eval_strategy: steps`，并令 `eval_steps` 与 `save_steps` 相同，因此每次保存检查点都会执行验证；也可改用独立验证集。验证仅在训练任务内运行，不恢复独立评估入口；快速对话测试是单独的 Hugging Face 工作区。

## 显存估算依据

- 扫描本地 `safetensors`、`bin`、`pt` 或 `pth` 权重，并避免重复统计同一模型的多种格式。对于未量化的 safetensors，直接解析文件头中的张量形状和数据区间，不加载权重即可获得准确参数量；量化权重改用 `config.json` 的模型结构计算逻辑参数量。
- 从模型配置读取层数、隐藏维度、中间层维度、GQA 的 KV 头、MoE 专家数/每 token 激活专家数、词表和视觉编码器结构。
- 将单设备峰值拆成四部分：已加载模型权重、可训练参数的梯度/优化器/主权重、峰值激活值，以及运行时/通信桶/显存分配器预留。界面会逐项显示，便于判断误差来自哪一部分。
- 从最终训练配置读取微调方式、用户选择的量化、精度、序列长度、训练及验证批次、LoRA rank、Freeze 层数、优化器、BAdam、训练阶段、ZeRO/offload、设备数和 Liger 状态。
- 激活值按注意力投影、实际激活的 MoE 中间层、梯度检查点、全词表 logits 和融合损失分别计算；梯度检查点开启和关闭不再只套用一个固定倍率。
- ZeRO-2 分片梯度和优化器状态，ZeRO-3 还分片模型权重并保留最大层聚合/通信空间；CPU offload 只扣除实际可卸载的部分。普通多卡 DDP 仍按每卡完整副本计算。
- 对多模态模型分别估算视觉塔前向/反向、视觉投影器和语言模型，并纳入冻结状态、patch/merge 大小以及最大图像、视频像素数。
- 开启验证时，验证批次按“仅前向”单独估算，再与训练步骤峰值取较大者；不会再把验证 batch 错当成需要保存反向激活的训练 batch。
- 推荐值为估计峰值的 `110%`。该估算用于启动前风险筛查，不替代实际运行监控。
- 多模态样本的实际图片数量和视频帧数无法仅从模型目录得知；当前视频按 8 个采样帧估算。CUDA/ROCm/XPU 内核工作区及显存碎片也会随驱动变化，因此 10% 余量不是误差上限，不保证不会发生 OOM，实际占用仍需在目标模型、数据和设备上校准。
- 梯度累积影响有效批量大小，但不会增加单次前后向传播的峰值，因此不作为实时显存变化因素。

## 界面与交互

- 统一蓝灰配色，同时适配浅色与深色模式；页头和工作区导航合并，表单卡片、输入框与按需展开区域统一间距，小屏幕自动换行。
- 按钮提供悬停、键盘焦点和禁用状态；步骤条用于显示进度，前后切换通过页面底部的导航按钮完成。
- 隐藏的显存警告窗口不拦截点击；“返回调整配置”会关闭窗口并回到第 3 步。
- 合并操作读取合并页实际选择的适配器，重新展开检查点列表保留已选项。
- 切换界面语言只更新文案，不重置已经手动修改的训练参数。
- 微调方法名称在下拉框、推荐结果和最终摘要中均本地化，写入配置时仍使用 `full`、`freeze`、`lora`、`oft`。
- 表单右上角“？”提供参数作用与操作建议；支持鼠标悬浮、键盘 Tab 聚焦和点击，Escape 可移走提示焦点。帮助操作不会勾选表单复选框或改变参数。

## 本地依赖与启动

项目依赖已声明：

```text
bitsandbytes>=0.48.0,<=0.50.2
tensorboard>=2.14.0,<=2.21.0
```

公共依赖保持必装；Liger Kernel (`>=0.8.0`) 为条件加速依赖，由安装器按后端解析、检查后决定是否启用。

使用 Bash、Git Bash 或 WSL 自动检测设备、创建/复用 `.venv`、安装项目与指标依赖，并启动 WebUI：

```bash
bash start_webui.sh
```

Windows PowerShell 使用 `./start_webui.ps1`。两个入口共用 `scripts/bootstrap_webui.py`，支持 CUDA、XPU、ROCm、昇腾 NPU 和 CPU。详见 [设备依赖安装说明](DEPENDENCY_INSTALLATION.md)。

脚本先准备对应的 PyTorch 后端，再执行以下核心安装命令，并通过临时 constraints 文件保护已选定的硬件依赖版本：

```bash
python -m pip install -e .
python -m pip install -r requirements/metrics.txt
```

WebUI 默认地址为 `http://127.0.0.1:7860`。已有环境可使用 `SKIP_INSTALL=1 bash start_webui.sh` 跳过安装。

新建训练默认使用 TensorBoard。用户点击“开始训练”后，WebUI 会同时启动 TensorBoard 并打开监控面板；`logging_dir` 和 TensorBoard 的 `--logdir` 都绑定到该任务最终输出目录。默认从 `http://127.0.0.1:6006` 开始选择可用端口，也可在启动 WebUI 前使用 `TENSORBOARD_HOST` 和 `TENSORBOARD_PORT` 覆盖监听地址和首选端口。

手动启动 WebUI：

```bash
llamafactory-cli webui
```

当前业务 CLI：

```bash
llamafactory-cli train <config.yaml>
llamafactory-cli export <config.yaml>
llamafactory-cli webui
```

Liger Kernel 不再仅按设备品牌启用或关闭。安装器首先检查依赖是否会覆盖当前 PyTorch/Triton 后端；运行时检查 Liger 版本、Triton 驱动、小规模 RMSNorm 与融合损失的前向/反向运算，以及本地模型对应的适配接口。未通过时自动关闭 Liger，继续标准训练。WebUI 摘要、生成配置和显存估算使用同一检查结果；CLI 也执行检查并记录降级原因。检查结果按训练精度缓存在当前进程中，安装依赖或更新驱动后需要重启 WebUI。测试算子通过并不保证所有模型和训练设置均兼容。

Intel XPU 不再被笼统标注为“不支持 Liger”。当前 XPU 训练路径仍关闭 FlashAttention；bitsandbytes 与 TensorBoard 保持必装。

2026-10-06 的 Windows 安装器已处理通用 Liger wheel 与厂商 Triton 包名不一致的问题：Intel 保留 XPU Triton，NVIDIA/AMD 按 Torch 版本匹配 `triton-windows`，生成有明确标记的本地 Liger 依赖适配包。当前工作区的 Intel XPU 已通过 Liger 算子检查和微型 LoRA 单步训练。安装命令与限制见 [完整指南](../PROJECT_INSTALLATION_AND_USAGE.md) 第 6 节；其他 GPU 尚未实机验证。

## 维护约定

- 不在 WebUI 业务组件中硬编码中文或其他界面文案；新增可见文本必须进入 `src/llamafactory/webui/locales.py` 或其引入的 `*_locales.py` 资源模块。
- 页面行为改变时，同步更新五种语言的引导文案和本文档。
- 显存相关参数变化后必须立即刷新第 3 步估算，同时使第 4 步的旧检查失效；训练启动前必须基于最终配置重新检查。
- 模型加载必须保持 `local_files_only=True`，避免训练节点发生隐式网络下载。
