# Cyrene Yield 训练界面：现行说明与改进点

> 更新日期：2026-09-03  
> 基础项目：LLaMA Factory  
> 集成目标：`Cyrene-Yield/develop/plugins/llama-factory-training`

## 与原版 LLaMA Factory 的主要差异

| 项目 | 当前实现 |
| --- | --- |
| 产品范围 | WebUI 只保留引导式训练和适配器合并；CLI 业务入口只保留训练与模型合并/导出。 |
| 模型来源 | 只读取本机已有模型目录，不提供 Hugging Face、ModelScope 或其他模型下载入口。 |
| 初始配置 | 根据训练目标、优化重点、检测到的 GPU 和本地权重文件大小自动生成。 |
| 参数展示 | 普通用户只看到“显存与速度”或“学习质量”一个分支；兼容参数使用安全默认值，不显示在引导流程中。 |
| 加速方式 | 默认使用 `liger_kernel`，不再使用 `auto`。 |
| 显存检查 | 参数配置阶段实时读取 `config.json`、本地权重文件和当前训练配置，估算单设备峰值并增加 10% 安全余量；启动前使用相同口径再次检查。 |
| 风险控制 | 显存不足、低于建议值或无法检测时不推荐启动；强制训练必须在警告窗口中二次确认。 |
| 多语言 | 可见文本集中在本地化资源中，当前支持英语、俄语、简体中文、韩语和日语，默认显示简体中文。 |
| 适配器合并 | 保留本地适配器合并；Hub 上传和原始 JSON 参数不再出现在 WebUI 中。 |

## 当前四步流程

1. **模型与目标**：输入包含 `config.json` 和权重文件的本地模型目录，选择训练目标和优化重点。硬件自动检测，推荐配置随选择即时更新。
2. **选择数据**：只展示与训练目标匹配的数据集，并允许先预览样本。
3. **按需调整**：可直接采用推荐值，也可以只修改显存/速度参数或学习质量参数。进入本步骤后立即显示显存估算；修改精度、量化、加速方式、序列长度或单卡批处理大小时自动重算。
4. **安全检查**：确认输出目录和配置，使用最终参数重新执行显存检查；通过后显示训练按钮。

训练启动时，最终配置会自动保存到任务输出目录，不再要求用户单独管理配置文件。

## 显存估算依据

- 扫描本地 `safetensors`、`bin`、`pt` 或 `pth` 权重，并避免重复统计同一模型的多种格式。
- 从模型配置读取层数、隐藏维度、中间层维度、词表和注意力结构。
- 从最终训练配置读取微调方式、量化、精度、序列长度、批次、LoRA rank、训练阶段、设备数和加速方式。
- 推荐值为估计峰值的 `110%`。该估算用于启动前风险筛查，不替代实际运行监控。
- 梯度累积影响有效批量大小，但不会增加单次前后向传播的峰值，因此不作为实时显存变化因素。

## 本地依赖与启动

项目依赖已声明：

```text
liger-kernel>=0.8.0
```

安装项目要求的依赖后启动：

```bash
llamafactory-cli webui
```

当前业务 CLI：

```bash
llamafactory-cli train <config.yaml>
llamafactory-cli export <config.yaml>
llamafactory-cli webui
```

Liger Kernel 需要其支持的 PyTorch、CUDA 和 Triton 环境；Windows 原生环境可能没有可用的 Triton wheel，正式训练建议使用受支持的 Linux/CUDA 运行环境。

## 维护约定

- 不在 WebUI 业务组件中硬编码中文或其他界面文案；新增可见文本必须进入 `src/llamafactory/webui/locales.py`。
- 页面行为改变时，同步更新五种语言的引导文案和本文档。
- 显存相关参数变化后必须立即刷新第 3 步估算，同时使第 4 步的旧检查失效；训练启动前必须基于最终配置重新检查。
- 模型加载必须保持 `local_files_only=True`，避免训练节点发生隐式网络下载。
